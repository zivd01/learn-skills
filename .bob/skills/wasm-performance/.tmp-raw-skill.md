# WebAssembly Performance Optimization

Follow these steps whenever the user wants to improve the performance of a WASM module,
diagnose bottlenecks, or set up a build pipeline for WASM targets.

## Step 1 — Identify the Toolchain and Language

Ask the user (using `ask_followup_question`) which source language and toolchain they are using:
- **Rust + wasm-pack** — `wasm-pack build --release --target web`
- **C / C++ + Emscripten** — `emcc -O3 -s WASM=1`
- **AssemblyScript** — `asc src/index.ts -O3 -o out.wasm`
- **Go (TinyGo)** — `tinygo build -o out.wasm -target wasm ./...`

## Step 2 — Inspect the Binary with wasm-objdump / wasm-opt

Run the following diagnostics (adapt path to the actual `.wasm` output):

```bash
# Size breakdown by section
wasm-objdump -h output.wasm

# Disassemble top-level exports
wasm-objdump -x output.wasm | grep export

# Run wasm-opt for quick wins (Binaryen)
wasm-opt -O3 --enable-simd output.wasm -o output.opt.wasm
```

Use `execute_command` to run these and report the before/after file sizes.

## Step 3 — Memory Layout & Linear Memory

1. Check that the linear memory initial size matches the working set (avoid over-allocation).
2. For **Rust**: ensure `wee_alloc` or `dlmalloc` is configured in `Cargo.toml`.
3. For **C/C++**: use `-s INITIAL_MEMORY=` and `-s ALLOW_MEMORY_GROWTH=0` unless growth is needed.
4. Avoid frequent `malloc`/`free` cycles in hot paths — pre-allocate buffers.

## Step 4 — SIMD Vectorization

If the target environment supports WASM SIMD (V8 ≥ 8.6, SpiderMonkey ≥ 89, Node ≥ 16):

- **Rust**: add `target-feature = "+simd128"` to `.cargo/config.toml`.
- **Emscripten**: add `-msimd128 -msse4.2` flags.
- **wasm-opt**: always pass `--enable-simd` when post-processing.

Verify SIMD is active by running:
```bash
wasm-objdump -d output.opt.wasm | grep -c "v128"
```

## Step 5 — JS ↔ WASM Boundary Crossings

Every call from JavaScript into WASM (or vice-versa) carries overhead. Optimize by:
1. **Batching calls** — pass arrays instead of individual values.
2. **Sharing memory directly** — use `WebAssembly.Memory` and typed arrays (`Float32Array`, `Uint8Array`) to avoid copies.
3. **Avoiding string marshalling in hot loops** — pass integer handles instead.

## Step 6 — Profiling in the Browser

1. Open DevTools → Performance tab → record a trace while running the WASM workload.
2. Look for `wasm-function[N]` frames — map index `N` back to the source using DWARF debug info.
3. For Rust: build with `RUSTFLAGS=-g` and include `--debug` in wasm-pack to get DWARF.
4. For Emscripten: add `-g3 -gsource-map` flags.

## Step 7 — Report Findings

Summarize the optimization results:
- Before vs. after binary size (bytes).
- Before vs. after execution time (ms) from profiler.
- SIMD instructions count (from `wasm-objdump` grep).
- Memory usage delta.

Present results as a markdown table using inline chat reply.
